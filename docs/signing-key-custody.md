# Signing-Key Custody (Milestone N6)

The updater private key and platform signing credentials are collectively the
single highest-blast-radius secrets this project holds. Whoever has them can push
a signed, auto-installed "update" to every user's machine.

## What must never happen

- No agent (Engineer, QA, Test Manager, PM) ever sees, requests, or handles these
  credentials directly.
- They exist **only** as GitHub Actions repository secrets, referenced by name in
  workflow YAML.
- They must never be echoed to a log, pasted into a ticket/comment/chat message,
  or written into any file in this repo (committed or not).

## Required secrets (GitHub Actions → repo Settings → Secrets and variables → Actions)

| Secret name                          | Platform | Purpose                                                                                    |
| ------------------------------------ | -------- | ------------------------------------------------------------------------------------------ |
| `TAURI_SIGNING_PRIVATE_KEY`          | All      | Signs updater artifacts; generated by `tauri signer generate` (below), outside the repo    |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | All      | Password chosen during `tauri signer generate` (omit if the key has none)                  |
| `APPLE_SIGNING_IDENTITY`             | macOS    | Developer ID Application certificate common name                                           |
| `APPLE_CERTIFICATE`                  | macOS    | Base64-encoded `.p12` certificate                                                          |
| `APPLE_CERTIFICATE_PASSWORD`         | macOS    | `.p12` passphrase                                                                          |
| `APPLE_ID`                           | macOS    | Apple ID for notarization                                                                  |
| `APPLE_PASSWORD`                     | macOS    | App-specific password (generated at appleid.apple.com, **not** the real Apple ID password) |
| `APPLE_TEAM_ID`                      | macOS    | Team ID from Apple Developer account                                                       |
| `WINDOWS_CERTIFICATE`                | Windows  | Base64-encoded `.pfx` code-signing certificate                                             |
| `WINDOWS_CERTIFICATE_PASSWORD`       | Windows  | `.pfx` passphrase                                                                          |

## Updater keypair generation (operator step)

Run on the operator's actual macOS/Linux machine (not in a sandbox/CI), from the
repo root (the CLI is a local devDependency, hence `npx`):

```bash
npx tauri signer generate -w ~/.tauri/vocab-automator.key
```

This writes the private key to `~/.tauri/vocab-automator.key` and the public key
to `~/.tauri/vocab-automator.key.pub`: outside the repository, so no `git add`
can pick either up. The command is interactive (password prompt) and cannot run
in a headless environment.

After generation:

1. Replace `KEYS_PLACEHOLDER_REPLACE_AFTER_GENERATION` in `src-tauri/tauri.conf.json`
   → `plugins.updater.pubkey` with the contents of the `.pub` file.
2. Set `TAURI_SIGNING_PRIVATE_KEY` as a GitHub Actions secret — and nowhere else.
3. Store the password securely (password manager, not in this repo).

## Release gate

Publishing and releasing remain deliberate, human-triggered actions (Tier 2/3 per
SOUL.md). The CI pipeline (N5) builds and publishes automatically on tag push,
but the tag push itself is a deliberate operator action — no agent triggers it.

## Where the pipeline lives

`.github/workflows/release.yml` (Milestone N5) consumes exactly the secrets in
the table above, by name; the `APPLE_*` ones reach only the macOS jobs and the
Windows certificate only its import step. Its preflight job
(`scripts/release-preflight.mjs`, tested by `scripts/release-preflight.test.ts`)
refuses to build unless `plugins.updater.pubkey` decodes the way the updater
plugin decodes it — a minisign public key, not the placeholder, not empty and
not a secret key (one pasted there must be treated as leaked: rotate it) — and
refuses a tag that differs from `src-tauri/tauri.conf.json`'s `version`. The
`GITHUB_TOKEN` is read-only except in the build job, and no checkout stores it
in `.git/config`.

`tauri.conf.json` names no signing identity: the CLI reads `APPLE_SIGNING_IDENTITY`
(or the identity of the imported `APPLE_CERTIFICATE`) from the environment, and a
local bundle without them is not codesigned. A plain local `npm run tauri build`
still stops after bundling, at the updater signature (`bundle.createUpdaterArtifacts`),
because only CI has `TAURI_SIGNING_PRIVATE_KEY`: build locally with
`npm run tauri build -- --no-sign` (every bundle, nothing signed) or `-- --no-bundle`.
Never copy the release key onto a development machine to get past that.
