# Signing-Key Custody (Milestone N6)

The updater private key and platform signing credentials are collectively the
single highest-blast-radius secrets this project holds. Whoever has them can push
a signed, auto-installed "update" to every user's machine.

## What must never happen

- No agent (Engineer, QA, Test Manager, PM) ever sees, requests, or handles these
  credentials directly.
- They exist **only** as GitHub Actions repository secrets, referenced by name in
  workflow YAML.
- They must never be echoed to a log, pasted into a ticket/comment/chat message,
  or written into any file in this repo (committed or not).

## Required secrets (GitHub Actions → repo Settings → Secrets and variables → Actions)

| Secret name                          | Platform | Purpose                                                                                    |
| ------------------------------------ | -------- | ------------------------------------------------------------------------------------------ |
| `TAURI_SIGNING_PRIVATE_KEY`          | All      | Signs updater artifacts; generated by `tauri signer generate -w src-tauri/`                |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | All      | Password chosen during `tauri signer generate` (omit if the key has none)                  |
| `APPLE_SIGNING_IDENTITY`             | macOS    | Developer ID Application certificate common name                                           |
| `APPLE_CERTIFICATE`                  | macOS    | Base64-encoded `.p12` certificate                                                          |
| `APPLE_CERTIFICATE_PASSWORD`         | macOS    | `.p12` passphrase                                                                          |
| `APPLE_ID`                           | macOS    | Apple ID for notarization                                                                  |
| `APPLE_PASSWORD`                     | macOS    | App-specific password (generated at appleid.apple.com, **not** the real Apple ID password) |
| `APPLE_TEAM_ID`                      | macOS    | Team ID from Apple Developer account                                                       |
| `WINDOWS_CERTIFICATE`                | Windows  | Base64-encoded `.pfx` code-signing certificate                                             |
| `WINDOWS_CERTIFICATE_PASSWORD`       | Windows  | `.pfx` passphrase                                                                          |

## Updater keypair generation (operator step)

Run on the operator's actual macOS/Linux machine (not in a sandbox/CI):

```bash
cd src-tauri/
tauri signer generate
```

This produces a public/private keypair. The command is interactive (password
prompt) and cannot run in a headless environment.

After generation:

1. Replace `KEYS_PLACEHOLDER_REPLACE_AFTER_GENERATION` in `tauri.conf.json`
   → `plugins.updater.pubkey` with the generated public key.
2. Set `TAURI_SIGNING_PRIVATE_KEY` as a GitHub Actions secret — and nowhere else.
3. Store the password securely (password manager, not in this repo).

## Release gate

Publishing and releasing remain deliberate, human-triggered actions (Tier 2/3 per
SOUL.md). The CI pipeline (N5) builds and publishes automatically on tag push,
but the tag push itself is a deliberate operator action — no agent triggers it.

## Where the pipeline lives

`.github/workflows/release.yml` (Milestone N5) consumes exactly the secrets in
the table above, by name. Its preflight job refuses to build while
`plugins.updater.pubkey` is still `KEYS_PLACEHOLDER_REPLACE_AFTER_GENERATION`
or while the pushed tag differs from `src-tauri/tauri.conf.json`'s `version`.
