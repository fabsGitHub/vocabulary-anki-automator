# Bundled HSK 3.0 curriculum

Decision 9 ships the HSK curriculum as static data compiled into vocab-core
(`include_str!` in `src/curriculum.rs`), so neither app makes a network call
for it. Everything here is generated by `tools/hsk-import` from pinned upstream
commits and reviewed as a diff; do not edit the generated files by hand.

| file                                | what                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------- |
| `hsk_curriculum.json`               | 10,969 `CurriculumItem`s, one per line, `None` fields omitted (generated) |
| `hsk_sources.json`                  | the pinned upstream files: URL, SHA-256 and size of each                  |
| `hsk_meaning_de.json`               | German meanings by hanzi, merged by `build` (written by `backfill-de`)    |
| `LICENSE-complete-hsk-vocabulary`   | MIT license of drkameleon/complete-hsk-vocabulary                         |
| `LICENSE-hsk30`                     | MIT license of ivankra/hsk30                                              |
| `NOTICE-CC-CEDICT`                  | attribution and license of the dictionary data (CC BY-SA 4.0)             |

## Provenance and licenses

Both upstream repositories are MIT-licensed; their license texts, downloaded
from the pinned commits and covered by the manifest, are the two `LICENSE-*`
files. The dictionary data is not only theirs, though: complete-hsk-vocabulary
builds each word's forms (traditional headword, pinyin, definitions) from
[CC-CEDICT](https://www.mdbg.net/chinese/dictionary?page=cc-cedict) entries and
credits it for the definitions, and CC-CEDICT is licensed under
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). So `meaning_en`,
`traditional` and `pinyin`, and anything derived from them (such as German
meanings machine-translated from `meaning_en` by `backfill-de`), are CC BY-SA 4.0:
whoever distributes them, in this file or compiled into the apps and the web
build, must credit CC-CEDICT and offer the adapted data under the same license.
`NOTICE-CC-CEDICT` (written by hand, not by the tool) holds that attribution.
Neither app nor the web build shows these notices yet, and the workspace's
`license = "MIT"` describes the code only: both are to be settled before the
first release (IMPLEMENTATION_PLAN.md, "Final audit").

- **[drkameleon/complete-hsk-vocabulary](https://github.com/drkameleon/complete-hsk-vocabulary)**
  at `7ac65bf1a6387d35f1ade478906172a19311c7f9`: `wordlists/exclusive/new/1.json`
  to `7.json`, the words new at each HSK 3.0 level, with simplified and
  traditional forms, tone-marked pinyin, English meanings (CC-CEDICT), part of
  speech and a frequency rank. File 7 is the combined 7–9 band, so
  `hsk_level` 7 means "7–9" (docs/architecture.md § 12 item 5). This is the
  source of every field in the curriculum.
- **[ivankra/hsk30](https://github.com/ivankra/hsk30)** at
  `4ff9e3915ce87baaecd7ebe263085573a4ea3192`: `hsk30.csv`, the official HSK 3.0
  word list (11,092 rows), one row per reading. It contributes no field; the
  build uses it to pick the right reading of each word (below) and to report
  where the two upstreams disagree.

`hsk_sources.json` was recorded on 2026-10-31 by `fetch --from`, from a mirror
of the ten pinned URLs downloaded with curl: the tool's own HTTP client could
not run TLS in the sandbox it was developed in (see `meaning_de` below). Each
file was also checked against the git blob hash GitHub's API reports for the
pinned commit, and all ten matched. A second, independent download of the
ten URLs reproduced every hash, and `build` from it reproduces
`hsk_curriculum.json` byte for byte. Any later `fetch`, mirrored or
downloaded, must reproduce these hashes exactly.

## How an upstream entry becomes an item

- `hanzi` = `simplified`; `hsk_level` = the file number (no level field in
  the exclusive files); `frequency` = upstream's rank (lower is more
  frequent; `1000000` is upstream's placeholder for 85 unranked words).
- `traditional`, `pinyin` and `meaning_en` come from **one chosen form** of
  the entry: `meaning_en` is that form's meanings joined with `"; "`, `pos`
  the entry's tags joined with `","`.
- `curriculum_order` numbers the items 0..n by (`hsk_level`, `frequency`,
  `hanzi`). A word in several level files is kept at its lowest level, so
  `hanzi` and `curriculum_order` are unique, as the store requires. (The
  pinned files have no duplicates.)
- Fields without a source stay empty and are omitted from the JSON:
  `meaning_de` (see below), `cloze_sentence`, the example sentence fields and
  the audio/image paths.

### Choosing the form

IMPLEMENTATION_PLAN.md said to take each entry's first form. 850 entries have
several forms, in CC-CEDICT's dictionary order, and for many common words the
first form is not the HSK word: 吧 starts with the loanword `bā` ("bar"), 还
with the surname `Huán`, 中 with the proper noun `Zhōng`. Taking it would have
taught wrong pinyin and meanings for exactly the words a learner meets first.
The build picks, in order:

1. the form whose reading equals the official reading of the word at its
   lowest official level (lowest ID on a tie), ignoring spaces, `'`, `-` and
   case (Unicode NFC); among several, the one with the official
   capitalization, then one not dominated by penalty meanings, then one with
   the official list's traditional form, then the one with the smallest
   share of penalty meanings, then the official list's first traditional
   form (冲 is `衝|沖`). Several forms share a reading because CC-CEDICT
   has one entry per traditional headword, and upstream lists them by code
   point: without the traditional form, 后 was "empress" (后) instead of
   "behind" (後), 当 "ding dong" (噹) instead of "to be" (當), 系 "to
   connect" (係) instead of "department" (系) and 台 "(classical) you"
   instead of "platform" (臺); 46 items changed when these preferences were
   added, most of them from a variant's or another word's meanings;
   **1b.** else the form that differs from that official reading only in
   neutral tones (CC-CEDICT `hǎo chu`, official `hǎochù`), fewest differences
   first. This step is not in the plan: without it, 好处 came out as `hǎo chǔ`
   ("easy to get along with"), 恶心 as `è xīn` ("vice") and 分量 as `fēn liàng`
   ("vector component");
2. else the form whose reading equals the `pinyin` crate's default reading
   (per character, joined by spaces);
3. else the first form not dominated by penalty meanings (`surname`,
   `variant of`, `old variant`, `(onom.)`, `abbr. for`, `(loanword)`,
   `erhua variant`, `Japanese variant` anywhere, or `used in` / `see ` at
   the start; dominated = no meanings or more than half of them penalties);
4. else the first form.

This build: 10,119 single-form entries; of the 850 multi-form entries, rule 1
decided 844 and rule 1b 6 (那里, 起来, 好处, 关系, 恶心, 分量); rules 2–4 decided
none. Every word has an official row and no level differs from the official
list. All but 10 items have the official traditional form: for 7 (恶心,
复习, 扎实, 家伙, 局限, 动荡, 哗然) upstream files the official form only as a
cross-reference ("variant of 复习"), so the form with the meanings wins, and
3 (尽可能, 特制, 效仿) are single-form entries. The build refuses to write
the file unless these spot checks hold: 吧 ba, 了 le, 的 de, 还 hái, 长 cháng,
行 xíng, 都 dōu, 好 hǎo, 要 yào, 看 kàn, 会 huì, 中 zhōng, 少 shǎo, 大 dà, 没 méi,
地 de.

### Pinyin repairs

The pinyin is stored the way cards use it: tone marks, one space between
syllables, an erhua `r` part of its syllable as in the official list
(`yīdiǎnr`). Some upstream readings needed repair (89 items, all listed by
`build`):

- CC-CEDICT notation leaking into tone-marked text: `lu:è` → `lüè` (策略,
  战略, ...), a neutral-tone `5` (`yǒukòngr5` → `yǒukòngr`), bopomofo's `˙`
  (`guī ˙nu:` → `guī nü`), a tone mark on the wrong vowel (奥运会 `Aò` →
  `Ào`);
- readings written solid or partly solid (`diàndòngchē`, `zhè shíhòu`): split
  into one syllable per character by matching each character's reading,
  with an erhua `r` kept on the syllable before it (`xiào huar`); one
  character whose default reading is another one gets the letters the
  others leave (着眼于 `zhuóyǎn yú` → `zhuó yǎn yú`);
- erhua written with CC-CEDICT's lone `r` (47 items, `yī diǎn r` → `yī diǎnr`,
  哪儿 `nǎ r` → `nǎr`), so every erhua word is spelled the same way.

### Where the reading differs from the official list

The pinyin is the chosen form's, as the plan specifies, so 159 items do not
match the official list letter for letter. 148 differ only in neutral tones,
where CC-CEDICT and the official list follow different conventions (`xué sheng`
/ `xuéshēng`, `běi biān` / `běibian`). The other 11 are single-form entries
where upstream knows only another standard reading: 血 / 出血 / 献血 `xuè` (HSK
`xiě`), 壳 `qiào` (`ké`), 泄露 `xiè lù` (`xièlòu`), 下载 `xià zǎi` (`xiàzài`), 定为
`dìng wèi` (`dìngwéi`), 尽可能 `jǐn kě néng` (`jìn kěnéng`), 一番 `yì fān` (`yīfān`),
一晃 `yī huǎng` (`yīhuàng`), and 不一会儿 `bù yī huǐr` (`bù yīhuìr`).

## Known gaps

- **No example sentences.** Neither upstream has any. J2's decision was to
  reuse the sentences of the user's own Anki deck where words overlap
  (`apkg-enrich`, below) and to leave the remaining ~9,600 words without one
  for now. Until then, captures use the pipeline's zh-CN fallback sentence.
- **No audio or images.** Captures fall back to live TTS.
- **Some upstream cross-references are cut short.** drkameleon's conversion
  dropped characters from a few CC-CEDICT references, and the build copies
  meanings verbatim: 交警 "traffic police (abbr. for 察)" (交通警察), 下功夫
  "see 夫", 无可厚非 "see 非", 立方 "abbr. for 米" (立方米), 佛 "(abbr. for
  陀)" (佛陀). Single-form entries whose only meaning is a reference (干吗
  "see 干嘛", 效仿 "see 仿效") have nothing better to choose from either.
- **`meaning_de` is empty: MyMemory's German is not good enough to ship
  unreviewed.** Neither upstream has German, so `backfill-de` translates the
  first sense of `meaning_en` (the text before the first top-level `;`) with
  MyMemory, English to German, into `hsk_meaning_de.json`, in curriculum
  order, saving after every item and stopping cleanly when the free quota is
  used up. The first sample run could not reach MyMemory (macOS's TLS stack
  fails inside the sandbox it ran in, `OSStatus -26276`). A second
  `--limit 120` run on 2026-10-31 did reach it, and about a third of the
  answers were wrong or garbage, because MyMemory answers single words from
  crowd-sourced translation memory: 在 "to exist" → `C . # .`, 他 "he" →
  `ts~brief f?`, 会 and 能 "can" → `Dose` (a tin can), 看, 见 and 看到 "to
  see" → `Megalithen zu sehen`, 手 "hand" → `werden.`, 都 "all" → `română`,
  你们 "you (plural)" left in English. Learn puts `meaning_de` on the back of
  a German learner's curriculum cards (`introduce_new_item`), so that sample
  was not committed and the file is still `{}`. Treat `backfill-de` output
  as a draft: correct it by hand (or replace it with a curated source)
  before `build` merges it.

## Regenerating

```bash
# 1. Download the pinned files; fails hard if any differs from hsk_sources.json.
#    (--from DIR reads a local mirror with the same layout instead.)
cargo run -p hsk-import -- fetch --out target/hsk-sources

# 2. Optional, repeatable: more German meanings (MyMemory's anonymous quota is
#    small; --email ADDR raises it). A draft: correct the new entries by hand
#    before step 3 (see "Known gaps").
cargo run -p hsk-import -- backfill-de --limit 120 \
  --curriculum crates/vocab-core/data/hsk_curriculum.json \
  --overrides crates/vocab-core/data/hsk_meaning_de.json

# 3. Rebuild, merging the German, and review the printed summary and the diff.
cargo run -p hsk-import -- build --source target/hsk-sources \
  --out crates/vocab-core/data/hsk_curriculum.json \
  --de-overrides crates/vocab-core/data/hsk_meaning_de.json

cargo test -p vocab-core --test bundled_curriculum --test chinese_capture
```

To re-pin to newer upstream commits, change the commits in
`tools/hsk-import/src/sources.rs`, delete `hsk_sources.json`, fetch, and
review the data diff and the summary.

### Enriching from your Anki deck (local only)

```bash
cargo run -p hsk-import -- apkg-enrich \
  --apkg "Chinese Vocabulary (HSK 1-4).apkg" \
  --curriculum crates/vocab-core/data/hsk_curriculum.json \
  --media-out "$HOME/HSK media"
```

This matches each note's `Chinese` field against `hanzi` and fills
`example_sentence_source`, `_pinyin` and `_target` from `Sentence`,
`Sentence Pinyin` and `English Sentence`. `example_sentence_target` is the
deck's **English** sentence for now, not German. It also copies the note's
`[sound:...]` and `<img>` media into `--media-out`, storing bare file names in
`vocab_audio_path`, `sentence_audio_path` and `image_path`. Existing values are
never overwritten. It needs a legacy package: an Anki 2.1.50+ export with
`collection.anki21b` is refused; re-export with "Support older Anki versions"
ticked. Never commit the media, and do not commit an enriched
`hsk_curriculum.json` unless the deck's license allows redistributing its
sentences: the deck is the user's, not part of the MIT sources. A later
`build` drops the enrichment, so re-run `apkg-enrich` after rebuilding.
